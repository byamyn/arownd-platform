# Arownd UI System v1.2

هذا الملف هو المرجع النصي العملي لتطبيق نظام Arownd Design System v1.2. المصدر التنفيذي للرموز هو `src/styles.css`، ويجب إبقاء هذا التوثيق متوافقاً معه.

## الهوية والألوان

| الدور | القيمة |
|---|---|
| Dark canvas | `#0A0A0A` |
| Light canvas | `#F5F5F5` |
| Light surfaces/cards | `#FFFFFF` |
| Lime Signal | `#C6F135` |
| Primary text (dark) | `#F5F5F5` |
| Primary text (light) | `#0A0A0A` |

- الوضع الداكن هو الأساس، مع دعم الوضع الفاتح وتفضيل النظام.
- استخدم الرموز الدلالية مثل `--color-bg-canvas` و`--color-action-primary` بدلاً من تكرار قيم HEX داخل JSX.
- ألوان الخرائط والبيانات الجغرافية قد تستخدم لوحة وظيفية منفصلة عندما يكون ذلك ضرورياً لتمييز الطرق والمياه والحدائق؛ لا تستخدمها لتلوين عناصر واجهة التطبيق العامة.

## الخطوط والطباعة

- Latin: Inter.
- Arabic: IBM Plex Sans Arabic.
- استخدم تسلسل أحجام النصوص والارتفاعات المعرفة في `src/styles.css`.
- تجنب أحجام الخطوط العشوائية أو تقليل وضوح النصوص الثانوية.

## المسافات والأشكال

- سلم المسافات الأساسي بمضاعفات 4px.
- نصف قطر البطاقة: 32px.
- الحقول والأزرار الأساسية: شكل Pill أو `--radius-control` بحسب نوع العنصر.
- ارتفاع التحكم الأساسي 48px والارتفاع المضغوط 44px.
- الحد الأدنى لهدف اللمس 44×44px.

## RTL وLTR

- يجب أن تعمل الواجهات بالعربية RTL والإنجليزية LTR.
- استخدم الخصائص المنطقية مثل `ms` و`me` و`ps` و`pe` و`start` و`end` بدلاً من الخصائص الفيزيائية متى أمكن.
- اعكس اتجاهات الأيقونات والتنقل عند الحاجة، ولا تفترض أن ترتيب DOM يتغير تلقائياً مع RTL.

## الوصول والحركة

- وفر أسماء وصولية للأزرار الأيقونية والحقول.
- اربط الحقول بتسميات واضحة، واستخدم `autocomplete` و`inputMode` المناسبين.
- حافظ على مؤشر `focus-visible` واضحاً والتنقل الكامل بلوحة المفاتيح.
- الحوارات واللوحات المنبثقة يجب أن تعلن دورها وعنوانها، وتحافظ على دورة التركيز وتعيده عند الإغلاق.
- احترم `prefers-reduced-motion`.
- يجب ألا يؤدي التكبير إلى 200% إلى فقدان المحتوى أو الوظائف.
- استخدم نصوص ترجمة من قواميس العربية والإنجليزية بدلاً من إضافة نصوص عربية ثابتة في خصائص الوصول.

## قواعد التنفيذ

1. لا تستخدم `window.alert` أو `window.confirm` أو `window.prompt`؛ استخدم مكونات التطبيق المعتمدة.
2. لا تضف ألوان HEX جديدة داخل `className` أو JSX؛ أضف رمزاً دلالياً عند الحاجة.
3. لا تحذف aliases القديمة من `src/styles.css` دون مراجعة جميع المستهلكين.
4. لا تستخدم `alt` فارغاً إلا للصورة الزخرفية التي لا تضيف معنى.
5. اجعل حالات التحميل والخطأ والفراغ والنجاح واضحة، مع إجراء إعادة المحاولة عندما يكون مناسباً.
6. اختبر RTL وLTR، الوضعين الفاتح والداكن، لوحة المفاتيح، وتقليل الحركة.

## PWA

- لون الخلفية الفاتحة: `#F5F5F5`.
- لون شريط المتصفح الداكن: `#0A0A0A`.
- يجب أن يتطابق `manifest.webmanifest` و`manifest.json`، وأن تعكس أيقونات التطبيق لوحة الهوية نفسها.
