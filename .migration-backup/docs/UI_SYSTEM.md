# Arownd UI System

> **Project:** Arownd  
> **Owner:** byamyn  
> **Repository:** [byamyn/arownd-platform](https://github.com/byamyn/arownd-platform)  
> **Status:** Implementation guide; source of truth for tokens is src/styles.css.

هذا الملف هو المرجع العملي لتطبيق نظام واجهة Arownd. عند اختلاف الوثيقة مع التنفيذ، افحص src/styles.css وحدّث الوثيقة بعد التحقق من القيم الفعلية.

## الهوية والألوان

| الدور | القيمة |
|---|---|
| Dark canvas | #0A0A0A |
| Light canvas | #F5F5F5 |
| Light surfaces/cards | #FFFFFF |
| Lime Signal | #C6F135 |
| Primary text (dark) | #F5F5F5 |
| Primary text (light) | #0A0A0A |

- ادعم الوضع الداكن والفاتح.
- استخدم الرموز الدلالية المعرّفة في CSS بدل تكرار قيم HEX داخل JSX.
- لا تستخدم ألوان الخرائط لتلوين عناصر الواجهة العامة.

## الخطوط والطباعة

- Latin: Inter.
- Arabic: IBM Plex Sans Arabic.
- التزم بتدرج الأحجام وارتفاعات الأسطر المعرفة في CSS.
- حافظ على وضوح النصوص الثانوية وتباينها.

## المسافات والأشكال

- سلم المسافات الأساسي بمضاعفات 4px.
- نصف قطر البطاقة المرجعي: 32px، ما لم يحدد المكوّن رمزًا مختلفًا.
- استخدم Pill أو رمز نصف القطر الدلالي للتحكم بحسب نوعه.
- ارتفاع التحكم الأساسي المستهدف 48px والمضغوط 44px.
- الحد الأدنى المستهدف لهدف اللمس 44×44px.

## RTL وLTR

- العربية وRTL هما الأساس، مع الحفاظ على دعم LTR.
- استخدم الخصائص المنطقية مثل ms وme وps وpe وstart وend.
- لا تفترض أن ترتيب DOM يتغير تلقائيًا مع RTL.
- راجع اتجاه الأيقونات والأسهم والتنقل في الاتجاهين.

## الوصول والحركة

- وفر أسماء وصولية للأزرار الأيقونية والحقول.
- اربط الحقول بتسميات واضحة واستخدم autocomplete وinputMode المناسبين.
- حافظ على مؤشر focus-visible واضحًا والتنقل بلوحة المفاتيح.
- يجب أن تحافظ الحوارات واللوحات على دورة التركيز وإعادته عند الإغلاق.
- احترم prefers-reduced-motion.
- اختبر التكبير حتى 200% دون فقد المحتوى أو الوظائف.
- استخدم مفاتيح القواميس للنصوص الظاهرة وأسماء الوصول.

## قواعد التنفيذ

1. لا تستخدم window.alert أو window.confirm أو window.prompt.
2. لا تضف ألوان HEX جديدة داخل JSX؛ أضف رمزًا دلاليًا عند الحاجة.
3. لا تحذف CSS aliases قديمة دون مراجعة المستهلكين.
4. لا تستخدم alt فارغًا إلا للصورة الزخرفية.
5. صمّم حالات التحميل والخطأ والفراغ والنجاح، مع إعادة المحاولة عند الحاجة.
6. اختبر RTL وLTR، الوضعين، لوحة المفاتيح، وتقليل الحركة.
7. استخدم أهداف لمس مناسبة للموبايل، ولا تجعل المعلومات الأساسية معتمدة على hover.

## PWA

- خلفية فاتحة: #F5F5F5.
- شريط متصفح داكن: #0A0A0A.
- حافظ على توافق ملفات manifest وأيقونات التطبيق.
- اختبر التثبيت والتحديث على أجهزة ومتصفحات فعلية.

## النسخة العربية | نظام الواجهة والهوية

### شخصية العلامة

- **Lime Signal:** `#C6F135`
- **Dark:** `#0A0A0A`
- **Light:** `#F5F5F5`
- **Cards:** أبيض في الوضع الفاتح.
- **Typography:** Inter وIBM Plex Sans Arabic.

الطابع المطلوب: Premium، واضح، عملي، قليل الضوضاء البصرية، مع إبراز اللون الليموني كإشارة تفاعلية لا كخلفية مفرطة.

### قواعد الواجهة

1. العربية وRTL هما نقطة البداية، مع دعم LTR.
2. استخدم CSS logical properties مثل `ms-` و`me-` و`ps-` و`pe-`.
3. لا تضف نصوصًا ثابتة في JSX؛ استخدم مفاتيح `src/lib/i18n.ts` والقواميس.
4. حافظ على تطابق مفاتيح العربية والإنجليزية.
5. ادعم الوضعين الفاتح والداكن مع تباين مقروء.
6. اجعل أهداف اللمس مناسبة للهاتف.
7. صمّم حالات التحميل والفراغ والخطأ والنجاح لكل تدفق.
8. لا تعرض حالة نجاح قبل تأكيد الخادم.
9. استخدم مكونات التأكيد واللوحات المعتمدة بدل `alert` و`confirm`.

### اتساق المجال

استخدم `pickBestOffer()` و`evaluateBag()` بدل إنشاء منطق أسعار أو سلة مكرر. يجب أن تبقى مكونات العرض منفصلة عن قواعد الأعمال.

### معيار الجودة

كل شاشة جديدة يجب أن تكون متجاوبة، قابلة للوصول بلوحة المفاتيح، واضحة على الهاتف، ومتوافقة مع RTL وLTR والوضعين الفاتح والداكن.
