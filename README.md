## نظرة عامة

**Arownd** منصة تجارة محلية واكتشاف منتجات، صُممت لتسهيل وصول المستخدمين إلى المتاجر والعروض من حولهم، ومساعدة التجار على إدارة حضورهم الرقمي وعملياتهم اليومية.

تستهدف المنصة السوق الجزائري، وتجمع ثلاث تجارب أساسية:

| المتسوقون | التجار | شركات التوصيل |
|---|---|---|
| اكتشاف المنتجات والمتاجر ومقارنة العروض وإدارة الطلبات والحجوزات | إدارة المتجر والمنتجات والعروض والمخزون والطلبات | إدارة بيانات الشركة ومناطق التغطية والشحنات وتتبعها |

توجد كذلك مساحة إدارية لإدارة بعض جوانب المنصة.

> **حالة المشروع:** نسخة MVP قيد التطوير والتحضير للإطلاق التجريبي. وجود وظيفة في الكود لا يعني أنها اجتازت اختبارًا تشغيليًا شاملًا؛ راجع قسم [الجاهزية والقيود المعروفة](#الجاهزية-والقيود-المعروفة) قبل أي إطلاق عام.

## أبرز الإمكانات

### تجربة المتسوق
- تصفح الصفحة الرئيسية والتصنيفات والمنتجات والمتاجر.
- البحث والاستكشاف وعرض المتاجر والمنتجات على الخريطة.
- صفحات تفاصيل المنتجات والمتاجر.
- مقارنة عروض المتاجر للمنتج نفسه واختيار العرض المناسب.
- إدارة المفضلة وسلة التسوق.
- التحقق من السعر والتوفر والمخزون قبل إتمام الطلب.
- إنشاء الطلبات ومتابعة حالتها.
- حجز المنتجات للاستلام من المتجر.
- مراجعات وإشعارات وملف شخصي وإعدادات.
- التواصل مع المتجر عبر الهاتف أو WhatsApp عند توفر بيانات الاتصال.

### مساحة التاجر — Studio
- إدارة بيانات المتجر والمنتجات والعروض.
- رفع صور المنتجات وإدارتها.
- تحديث المخزون وحالة توفر المنتجات.
- البحث والتصفية وإدارة الطلبات والحجوزات.
- متابعة المعلومات الأساسية للمتجر ووسائل التواصل.

### خدمات التوصيل والإدارة
- تسجيل وإدارة بيانات شركات التوصيل.
- إدارة مناطق التغطية والخدمات.
- إدارة الشحنات وتحديث حالاتها وسجلات التتبع.
- صفحات إدارية للمتاجر وشركات التوصيل.
- وظائف للمحفظة وسجل المعاملات، مع ضرورة مراجعة صلاحياتها قبل الإطلاق.

### قدرات المنصة
- المصادقة وإدارة الجلسات عبر Supabase Auth.
- تحديثات لحظية لبعض البيانات عبر Supabase Realtime.
- تخزين الصور والملفات عبر Supabase Storage.
- دعم PWA وService Worker وتحديث التطبيق.
- إعدادات SEO وOpen Graph وsitemap وrobots.
- تكامل مراقبة الأخطاء عبر Sentry.
- اختبارات آلية باستخدام Vitest وTesting Library.

> توجد بعض أسماء الملفات والمعرّفات الداخلية القديمة التي تحمل اسم SooQy. لا تغيّرها آليًا؛ فقد ترتبط بالاستيرادات أو التخزين المحلي أو هوية تطبيق Android.

## البدء محليًا

### المتطلبات

- Node.js **22.x**
- npm
- Git
- مشروع Supabase

### التثبيت

```bash
git clone https://github.com/yaso33/arownd-v-0.git
cd arownd-v-0
npm ci
```

أنشئ ملف البيئة المحلي:

```bash
cp .env.example .env
```

أضف إعدادات مشروع Supabase إلى `.env`، ثم شغّل التطبيق:

```bash
npm run dev
```

سيعرض Vite عنوان خادم التطوير في الطرفية.

## إعدادات البيئة

راجع `.env.example` للحصول على القائمة المرجعية. المتغيرات الأساسية:

| المتغير | الاستخدام |
|---|---|
| `SUPABASE_URL` | عنوان مشروع Supabase |
| `SUPABASE_PUBLISHABLE_KEY` | المفتاح العام لعميل Supabase |
| `VITE_SUPABASE_URL` | عنوان Supabase المضمّن في حزمة المتصفح عند الحاجة |
| `VITE_SUPABASE_PUBLISHABLE_KEY` | المفتاح العام المضمّن في حزمة المتصفح عند الحاجة |
| `SUPABASE_SERVICE_ROLE_KEY` | عمليات الخادم الموثوقة فقط؛ سرّي للغاية |
| `SUPABASE_ANON_KEY` | متغير توافق اختياري |
| `SUPABASE_PROJECT_ID` | معرّف مشروع Supabase |
| `DATABASE_URL` | اتصال PostgreSQL لأدوات الهجرات المحلية |
| `VITE_GOOGLE_MAPS_API_KEY` | إعداد اختياري لبعض تكاملات الخرائط |

### قواعد أمنية

- لا ترفع ملف `.env` إلى Git.
- لا تضع `SUPABASE_SERVICE_ROLE_KEY` أو كلمة مرور قاعدة البيانات في كود المتصفح أو المستودع.
- المفتاح العام لا يغني عن سياسات RLS؛ يجب اختبار الصلاحيات لكل دور.
- لا تضف `DATABASE_URL` إلى إعدادات الاستضافة إلا عند وجود حاجة خادمية واضحة.
- إذا كُشفت بيانات سرية سابقًا، دوّرها وراجع تاريخ Git وصلاحيات الوصول.

## قاعدة البيانات والتخزين

تعتمد Arownd على Supabase وPostgreSQL. توجد الهجرات في:

```text
supabase/migrations/
```

تشمل مجالات البيانات الرئيسية المستخدمين والأدوار، المتاجر والمنتجات والعروض، الطلبات والحجوزات، المناطق والبلديات، التقييمات والإشعارات، شركات التوصيل والشحنات وسجلات التتبع، ومعاملات المحفظة.

توجد وظائف PostgreSQL RPC لعمليات مثل إنشاء الطلبات والحجوزات وبعض عمليات التاجر والمراجعات والإحصاءات.

### الهجرات

راجع محتوى الهجرات وترتيبها قبل تطبيقها:

```bash
node scripts/apply-migrations.mjs
```

ولبيئة التطوير التي تحتاج بيانات تجريبية، راجع خيارات السكربت أولًا:

```bash
node scripts/apply-migrations.mjs --seed
```

**لا تطبّق هجرات أو سكربتات تنظيف على الإنتاج قبل أخذ نسخة احتياطية ومراجعة أثر العملية.**

يستخدم Supabase Storage لصور المتاجر والمنتجات وملفات أخرى. اختبر أحجام الملفات وصلاحيات الوصول وسرعة الرفع وصلاحية الروابط في بيئة فعلية.

## النشر

### Vercel

إعداد النشر موجود في `vercel.json`، والدليل التفصيلي في [DEPLOY-VERCEL.md](./DEPLOY-VERCEL.md).

الإعداد الحالي:

- **Build Command:** `npm run build:vercel`
- **Output Directory:** `dist/client`
- **Framework Preset:** Other

الخطوات الأساسية:

1. اربط مستودع GitHub بمشروع Vercel.
2. أضف متغيرات Supabase المطلوبة إلى بيئات النشر المناسبة.
3. تأكد من توفر القيم المطلوبة وقت البناء.
4. نفّذ النشر وراجع سجلات Build وFunctions.
5. اضبط Site URL وRedirect URLs في Supabase Authentication لتطابق نطاق التطبيق.
6. اختبر تسجيل الدخول والصفحات الديناميكية والملفات الثابتة بعد النشر.

### Android

يعتمد تطبيق Android على Capacitor 8. الإعداد موجود في `capacitor.config.ts` ومجلد `android/`.

```bash
npm run build:mobile
npx cap sync android
```

إنشاء APK أو AAB يتطلب بيئة Android SDK وGradle مناسبة وإعداد توقيع إصدار صالح. لا تغيّر `applicationId` دون خطة ترحيل واضحة؛ فتغييره قد يؤثر في هوية التطبيق المثبّت وتحديثاته.

### PWA

ملفات PWA الأساسية:

- `public/manifest.webmanifest`
- `public/sw.js`
- `src/lib/pwa.ts`

اختبر التثبيت والتحديث والعمل بعد انقطاع الاتصال على أجهزة ومتصفحات فعلية. وجود Service Worker لا يعني أن كل سيناريوهات العمل دون اتصال مدعومة.

## الجاهزية والقيود المعروفة

هذه ملاحظات يجب أخذها في الحسبان قبل اعتبار المنصة جاهزة للإطلاق العام:

1. **الفحوص:** يجب تشغيل TypeScript وESLint والاختبارات والبناء على أحدث commit وتوثيق النتائج؛ لا تعتمد على نتائج قديمة.
2. **إنشاء الطلب والشحنة:** إنشاء الشحنة ليس جزءًا من معاملة قاعدة بيانات ذرّية واحدة مع الطلب؛ قد ينجح الطلب بينما تفشل خطوة الشحنة، ما يتطلب متابعة أو إعادة معالجة.
3. **منع تكرار الطلبات:** يلزم ضمان خادمي واضح لمنع الطلبات المكررة، لا الاكتفاء بحماية الواجهة.
4. **خيارات المنتجات:** يجب حسم هوية خيارات مثل المقاس واللون في السلة وعقد البيانات حتى لا تختلط خيارات مختلفة للعرض نفسه.
5. **صلاحيات شركات التوصيل والمحفظة:** راجع RLS وسياسات التحديث واختبرها بحسابات مستقلة؛ لا تفترض أن الواجهة وحدها تفرض الصلاحيات.
6. **اللغة:** القواميس العربية والإنجليزية موجودة، لكن الإنجليزية معطّلة حاليًا عبر `ENGLISH_ENABLED = false`؛ النسخة التجريبية عربية.
7. **الهوية التقنية القديمة:** لا تزال بعض المعرفات الداخلية والنطاقات وبيانات SEO بحاجة إلى مراجعة نهائية قبل اعتماد النطاق الرسمي.
8. **الأجهزة والأداء:** يلزم اختبار Android فعلي، وRTL، والوضعين الفاتح والداكن، ورفع الصور، واختبار تحميل تدريجي. لا يوجد ضمان أداء لعدد محدد من المستخدمين دون قياس فعلي.

### قائمة تحقق قبل الإطلاق

- [ ] تدوير أي أسرار سبق كشفها ومراجعة صلاحيات المستودع.

- [ ] مراجعة RLS لكل دور: متسوق، تاجر، إدارة، وشركة توصيل.
- [ ] اختبار دورة الطلب كاملة، بما فيها فشل إنشاء الشحنة ومنع الطلبات المكررة.
- [ ] اختبار إدارة المنتجات والصور والمخزون والطلبات.
- [ ] اختبار تسجيل شركات التوصيل وإدارة الشحنات والتتبع.
- [ ] قياس سرعة رفع الصور والتحقق من أحجامها وصلاحياتها.
- [ ] مراجعة النطاق النهائي وإعدادات OAuth وSEO وPWA.
- [ ] اختبار التطبيق على أجهزة فعلية وأحجام شاشات مختلفة.
